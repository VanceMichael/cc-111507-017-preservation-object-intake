# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 领取入口文件并记录元信息。structured 按 OCFL 清单领取指定版本（version 缺省 head）的逻辑文件；版本号非法或清单中不存在返回400，清单不可信或完全无法解释形成 rejected 收件（201），清单可信但部分内容缺失或摘要不符形成 partial，全部逻辑文件可靠取得才为 complete。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 每个指定版本逻辑文件一条，recordId 由对象 id、版本与逻辑路径组合而成；logicalPath 保留原路径，state 为 reliable、missing、rejected 或 blocked；content.contentPath 是实际领取的 manifest 内容路径，content.blob 为 SHA-256 寻址的本地内容。同一内容被多个逻辑路径或历史版本复用时 blob 只存一份、只下载一次，多条记录共享同一 blob 摘要，关系不丢失。coverage 给出 requestedVersion、selectedVersion、head、contentDirectory、逻辑文件数、可靠数、去重内容数、manifest 内容总数与历史未引用排除数。
