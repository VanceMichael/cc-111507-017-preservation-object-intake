# 数字馆藏保管交付来源格式

OCFL 1.1 对象，sha256/sha512 inventory digestAlgorithm，清单 sidecar 文件摘要覆盖原始 inventory 字节。/manifest 只给对象允许领取的相对资源，不作为文件语义。指定 version 缺省 head，version state 的 digest->logicalPaths 与 manifest digest->contentPaths 形成映射；可以择一有效内容副本但不能改动逻辑身份。contentDirectory 默认 content，根与所选版本清单应一致。逻辑/物理路径不允许绝对路径、..、空组件或越出对象根。历史未引用内容不在本次范围。

收件端强制核对：NAMASTE 对象声明（`0=ocfl_object_1.1`）实际取得且内容正确；根清单与所选版本目录的 `inventory.json` 都要有同算法 sidecar，sidecar 摘要必须覆盖各自原始清单字节；版本清单与根清单的 id、type、digestAlgorithm、head、contentDirectory、manifest、versions 必须相符（OCFL 要求字节一致）；manifest 内容路径必须位于 `版本/contentDirectory/` 布局内且通过对象根边界检查；下载内容按清单 digestAlgorithm 重新计算摘要并与 state/manifest 摘要核对。任一项不通过即拒绝领取内容并形成 rejected，缺内容或内容摘要不符形成 partial，均不得静默降级。只有所选版本 state 引用的摘要会触发内容下载，同一摘要只下载一次，manifest 中未被该版本引用的历史内容不领取。

`fixtures/scenarios.json` 给出本机来源入口和允许读取的资源；`GET /manifest` 返回同样的来源描述。`GET /trace` 返回当前进程内真实来源访问记录。资源接口为 `GET /files/百分号编码的资源名`，支持单段 Range、ETag 和 If-Match；资源名必须出现在来源清单中。数据不是新闻原文，不连接真实客户或设备。

格式参考：https://ocfl.io/1.1/spec/。本项目只承诺上文列出的范围；未列出扩展应保留原文并明确不支持，不能假装完整解析。
